2018 MacBook Air T2 × macOS Tahoe 26.7 攻略記録

2018年モデルのMacBook Airで、公式対応外となる macOS TahoeをT2向けOpenCore Legacy Patcherを使って起動できるか実験した。

実験概要

今回の目的は、2018 MacBook Air（MacBookAir8,1）に macOS Tahoe 26.7をインストールできるか確認すること。

普通にアップデートするのではなく、 T2 Mac向けに開発されているOpenCore Legacy Patcherの 非公式フォークを使用した。

結論から言うと、今回はインストーラーを起動して 言語選択画面まで到達したものの、その先へ進めず終了した。

ただし、USBインストーラー作成、OpenCore構築、 EFIへの導入、T2のセキュリティ設定変更、 Tahoeインストーラーの起動までは確認できた。

使用したMac

  • MacBook Air 2018
  • モデル：MacBookAir8,1
  • CPU：Intel Core i5 1.6GHz デュアルコア
  • メモリ：8GB
  • GPU：Intel UHD Graphics 617
  • T2チップ搭載
  • 現在のOS：macOS Sonoma 14.8.9

実験対象

  • macOS Tahoe 26.7
  • Build：25G229
  • OpenCore Legacy Patcher T2 fork
  • OCLP Version：4.0.0.190004.1

なぜTahoeを入れてみるのか

このMacBook Airは2018年モデルで、T2チップを搭載している。

Appleの公式対応範囲だけを見ると、この世代のMacは Tahoeの対象外となっている。

そこで、T2 Mac向けに開発されている OpenCore Legacy Patcherの実験的な環境を使って、 実際にどこまで進めるのかを試してみることにした。

「動くかもしれない」という情報を見るだけではなく、 実際に自分のMacで試して、途中経過と失敗地点を残す。

実験開始

1. OCLP T2版を準備

T2 Mac向けのOpenCore Legacy Patcher forkを使用。

今回使用したバージョン： 

4.0.0.190004.1

このバージョンはまだ一般利用向けの完成版ではなく、 実験的な段階である。

2. ダウンロードファイルを確認

ダウンロードしたパッケージについてSHA-256を確認。 

27441edf102101f6a965c4b74f2e757bdf19473c019fcc1b2bed21c4d44fc63

SHA256SUMSとの一致を確認した。

3. macOS Tahoeインストーラーを準備

OCLPからの自動抽出は途中で失敗した。

そのため、別の方法でInstallAssistant.pkgを展開し、 Tahoeのインストーラーアプリを作成。

その後、USBメモリへmacOS Tahoeインストーラーを作成した。

USBのボリューム名： 

Install macOS Tahoe

4. OpenCoreを構築

MacBookAir8,1を指定してOpenCoreを構築。

構築時にはT2 Macとして認識され、 Secure EnclaveやAPFS Keybagを保護するため、 ネイティブのSMBIOSを維持する設定となった。

OpenCoreはUSBのEFIへインストール。

T2側の設定

外部メディアから起動するため、 T2のセキュリティ設定を変更。

  • Find My：無効
  • Secure Boot：No Security
  • 外部メディアからの起動：許可

RecoveryのTerminalからも必要な設定を確認した。 

csrutil disable
csrutil authenticated-root disable

その後、Sonoma側から状態を確認。

Authenticated Rootは無効になっていることを確認した。

いよいよ起動

MacBook Airを再起動。

Optionキーから起動ディスクを選択し、 EFI Boot → OpenCore → Install macOS Tahoe の順番で起動した。

そして……

起動した

まず言語選択画面まで到達した。

つまり、

  • USBインストーラー作成成功
  • OpenCore起動成功
  • T2 Mac上でOpenCore経由のTahoeインストーラー起動成功
  • GUIの言語選択画面まで到達

ここまでは確認できた。

しかし、ここから先へ進まない

言語選択画面で停止。

日本語を選択したところ、 次へ進むボタンがグレーアウトした状態になった。

別の起動でもVerboseログを確認したが、 AppleKeyStore、Bluetooth、IOConsoleUsersなどの ログが流れたところで停止した。

また、以下のようなKernelCollections関連のエラーも確認された。 

Err(0xE)
System\Library\KernelCollections\BootKernelExtensions.kc
BootKernelExtensions.kc.development

Panicして再起動するというより、 インストーラーの起動途中で処理が進まなくなる状態だった。

何度か試した

USBを作り直したり、OpenCoreを確認したりしながら 複数回起動を試した。

結果として、同じような場所で停止する。

内蔵SSDの消去やSonoma環境の破壊は行わなかった。

既存環境を残したまま、外部USBからの実験だけで終了した。

今回確認できたこと

  • MacBookAir8,1でT2向けOpenCoreを起動できた
  • macOS Tahoe 26.7のUSBインストーラーを作成できた
  • OpenCore経由でTahoeインストーラーを起動できた
  • GUIの言語選択画面まで到達できた
  • 内蔵Sonoma環境を維持したまま実験できた
  • 現時点ではインストール完了まで到達できなかった

今回の結果

FAIL

macOS Tahoe 26.7のインストール完了には到達できなかった。

ただし、単純な「起動しなかった」という結果ではない。

T2 Mac上でOpenCoreを起動し、 Tahoeインストーラーを立ち上げ、 GUIまで到達するところまでは確認できた。

現在のT2向けOCLP環境では、 MacBookAir8,1でTahoeインストーラーを最後まで動作させるには まだ問題が残っていると考えられる。

今回の実験では、そこから先へ進むことはできなかった。

研究メモ

失敗したからといって、この実験が無駄だったわけではない。

「MacBookAir8,1ではTahoeが動かなかった」 だけではなく、

「どの環境を用意し、どこまで起動し、 どの地点で止まったのか」

まで記録することで、次に同じ実験をする人の基準点になる。

特にT2 Macは通常のIntel Macとは違う部分が多い。 今後OCLP側の対応が進んだ場合、 この記録を使って再実験できる。

次回の条件

  • OCLP T2 forkの新バージョンが公開された場合
  • Tahoeのアップデートで状況が変わった場合
  • MacBookAir8,1向けの新しい修正が入った場合
  • 今回停止したKernelCollections周辺の問題が解決した場合

条件が変わったら再挑戦する。
